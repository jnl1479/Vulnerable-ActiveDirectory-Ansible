Vulnerable-ActiveDirectory-Ansible

Overview
This project deploys a targeted Active Directory (AD) environment designed to simulate a high-security corporate network belonging to the Arasaka Corporation. It focuses on realistic misconfigurations often found in complex enterprise environments, specifically targeting identity management and Kerberos authentication protocols.

By deploying this lab, users can practice a multi-stage attack chain that transitions from unauthenticated information gathering to full credential recovery. This is an essential resource for security professionals looking to understand the intersection of Active Directory metadata leaks and Kerberos-based exploitation.

Vulnerability Description
The lab features two primary security flaws:

Information Leakage in AD Attributes: A service account (rbartmoss) has sensitive credential clues stored in the cleartext Description attribute, a common result of poor administrative automation.

AS-REP Roasting: A high-value target (sarasaka) is configured without requiring Kerberos pre-authentication. This allows an attacker to request an encrypted authentication ticket and crack it offline to recover the cleartext password.

Prerequisites
Target OS: Windows Server 2019/2022 (Domain Controller), Ubuntu 22.04 LTS (Attack Machine), Windows 10 (Attack Machine)

Ansible version: 2.9+

Required Python packages: pywinrm

Other requirements: - Internet connectivity on the attack machines to pull binaries.

Valid SSH/WinRM access to target nodes.

Competition Use Cases
Red Team: Practice "living off the land" by using built-in Windows tools ([ADSI], net use) and specialized binaries (Rubeus) to escalate privileges.

Blue Team: Use this to identify the specific Event IDs (e.g., 4768 - Kerberos Authentication Ticket requested) generated by AS-REP roasting and monitor for LDAP enumeration.

Grey Team (Scoring): Utilize this lab to verify if participants can successfully pivot from an unauthenticated state to a domain-user state within a time limit.

Technical Details
The Ansible playbook automates the following:

Forest/Domain Creation: Promotes the Windows target to a Domain Controller for arasaka.com.

User Provisioning: Creates rbartmoss and sarasaka with the specific vulnerable attributes described.

Security Policy Modification: Specifically disables Kerberos pre-authentication for the sarasaka account and sets a weak, crackable password for the AS-REP roast challenge. Configure the rbartmoss account to not require a password. 

Troubleshooting
WinRM Connection Refused: Ensure the ConfigureRemoting.ps1 script has been run on the Windows target to allow Ansible management.

Hashcat "Device Not Found": If running in a VM, ensure you use the --force flag as outlined in the Exploitation Guide to utilize the CPU.

Rubeus Execution Blocked: You may need to temporarily disable Windows Defender real-time protection.
